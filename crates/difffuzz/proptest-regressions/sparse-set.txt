# --- A: the two swap stores in `delete` treated as if they behaved alike ---
#
# Upstream's delete ends with
#     index = this.dense[this.size - 1];
#     this.dense[this.sparse[member]] = index;
#     this.sparse[index]              = this.sparse[member];
# and once an out-of-range `add` has pushed `size` past `length`, `index` is
# `undefined`: the first store still lands (as 0), the second becomes a
# string-keyed expando and leaves `sparse` untouched. The sabotage was to write
# `sparse[0]` for the second -- which is what a careful reading of the file as
# a whole, rather than statement by statement, produces. Found in 1,416 cases
# (6.6s) and shrunk from 200 ops to seven:
#
#     var s = new SparseSet(5);
#     s.add(0); s.add(1); s.add(2); s.add(4);
#     s.add(5);            // out of range: dense gets it, sparse does not,
#     s.add(5);            // size runs to 6 against a length of 5
#     s.delete(1);         // port sparse [1,1,2,0,3], upstream [0,1,2,0,3]
#

# --- C: the fuzzer's own `$forEach` rule applied its arithmetic too early ---
#
# NOT a sabotage, and not a port defect: this one was found by the first
# 20-second campaign after the `$forEach` op was added, on 2026-08-01. The
# `arg0+1` rule folded `+ 1` into the argument SELECTION, so an `undefined`
# callback argument became `NaN` -- which is not `undefined`, sailed past the
# skip that exists to keep NaN indexing out of the grammar, and reached
# `SparseSet.add(NaN)`. Upstream's `sparse[NaN]` comparison falls through and
# increments `size`; the port cannot follow, because mnemonist-core takes a
# `usize`. Shrunk to two operations:
#
#     var s = new SparseSet(0);
#     s.add(0);                                  // out of range: dense stays
#                                                // empty, size becomes 1
#     var fired = 0;
#     s.forEach(function (a, b) {                // a is undefined
#       if (a === undefined) return;
#       if (fired++ < 1) s.add(a + 1);
#     });
#     // upstream walked twice, the port once
#
# Fixed in fuzz/oracle.js by separating selection from arithmetic, with the
# skip in between. Kept so the ordering stays pinned: a future edit that folds
# them back together fails on this seed before any novel case runs.
