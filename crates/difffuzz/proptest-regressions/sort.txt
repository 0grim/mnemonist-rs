# --- 1. `indices` choosing its width from the TRUNCATED length ---
#
# Upstream's `exports.indices` uses its argument twice and coerces it
# differently each time: `getPointerArray` compares `length - 1` as a double,
# while the TypedArray constructor applies ToIndex and truncates. So
# `indices(256.5)` is a Uint16Array of 256 elements -- one width wider than 256
# elements need. The sabotage truncated first and passed the integer to
# `getPointerArray`, which is the obvious reading of the code and produces a
# Uint8Array.
#
# Invisible to test/sort.js, which calls `indices` exactly once, with 11.
# Found in 62 cases (0.3s) and shrunk to a single op:

#     m.indices(256.5);   // port Uint8Array, upstream Uint16Array
#
